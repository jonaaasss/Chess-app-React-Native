# Chess Playbook — Project Context

## What this app is

"Chess Playbook" (formerly "Chess Opening Flashcards"; the package id and slug are unchanged) is a React Native / Expo app for studying chess opening repertoires as flashcards. The user (Jonas) builds a repertoire per color (White/Black): **Repertoires → Openings → Cards**. Each card has one of three modes (see Data model). Personal project under active development; a Play Store release is planned but nothing is published yet.

## Data model (src/types.ts)

- `Repertoire` (`GroupId` `'white' | 'black'`) → `Opening` → `Card`. `Card.mode`: `'summary' | 'reactions' | 'plan'` (`'others'` = the removed "Front & back" type: `migrate()` deletes those cards and it is no longer offered). All modes use `Card.boards: ReactionBoard[]` (1–8 boards, `MAX_BOARDS` in `chess.ts`; 2 per row in the card editor). Under each board in the card editor and in Study (not in the board editor, not in the guide) `BoardShare` shows "29% of games (i)": how often the board's position comes up from the opening's start position, counting only the opponent's choices (your moves count as always played); tapping it explains this (`src/boardShare.ts`, live from the explorer cache; nothing when the board does not start from the opening's start position, its moves don't lead to its position (a board set up by hand) or there is no token).
  - **Summary** (`isPlanLike`, data on `back` like Plan): at most one per opening, always first (`getCards`, Study queue, pinned in the Cards list). In Study it runs through `PlanStudy` (unscored); an arrow's `notes.linkCardId` shows a link badge that opens the card in `CardViewerOverlay` (look-only; green "← Summary" back, full title; a Reactions card runs exactly as in Study but in preview mode (`ReactionStudy preview`: all moves auto-played with animation, variations walked, ‹ › and pause, no Hint/Show solution, Continue = back); a Plan card runs exactly as in Study (`PlanStudy viewer`, never scored); a pencil opens the Board editor; with `notes.linkBoardId` only that one board, chosen in the notes screen's "Board" dropdown; `src/linkTargets.ts`). The notes screen title names the arrow (colour and badge). New Summary and Plan cards default to Fast Revision.
- `Opening` also has `startPosition?` (chosen once when the opening is created, via `OpeningStartPositionOverlay`; every new board starts there) and `summary?` (free text shown blurred at the start of studying; syntax in `docs/IMPORT_REGELS.md`). `Card` also has `fastRevision?` (part of the quick daily run) and `overviewText?` (shown after the last board; auto-generated from the board descriptions when blank).
- **Study text lives on each board**, in one "Description" field: `board.front.text` for Reactions, `board.back.text` for Plan, and for Others whichever face is being viewed. `descriptionFace()` in `CardEditorOverlay.tsx` carries it over when the mode changes.
  - **Reactions**: a rules-accurate recorded game (`chessEngine.ts`) stored as a branching tree (`MoveNode`; `children[0]` = main line). In Study (`ReactionStudy`, also the link viewer with `viewer`, never scored) each board is walked along a fixed timeline (`buildTimeline`): at a branching point all choices are shown as numbered arrows (the move about to be played light, the others dark, colour by the order of branching points along the line: green, orange, red, blue), each choice is played to its end and rewound only to that branching point before the next choice. Order: on the main line the variations shortest first and the main line last; inside a variation its own continuation first. Played choices stay as one light numbered arrow. A switch "Play myself" / "Auto-play" in the fixed bottom bar between the pencil and Skip (`ReactionModeSwitch`, remembered, setting `reactionAutoPlay`; hidden in the preview pass and the guide; the selected mode light grey, not green). Above the board and a collapsible Description (`CollapsibleDescription`, state remembered for all cards, also in Plan/Summary). "Line k of N" names the current line; tapping it opens the lines tree and scrolls to it. « ‹ › : « back to the branching point of the last choice, ‹ › review the moves on the board (nothing moves meanwhile; › never plays your move). At the bottom a collapsible "N lines" tree (`buildTree`): the choices of the first branching point, each opening to the moves up to the next one and its choices; ▶ plays from that choice. Lines skipped by jumping are played before the board ends. The link viewer has the same fixed bottom bar as Study (pencil, Skip = back to the Summary). Editing from Study and the viewer (`onCardSaved`, saved by board id via `src/studyEdits.ts`; off in the guide): a pencil in the opened Description (`textDialog`, all card types), and after a wrong but legal move of yours a snackbar "Use this move": it replaces the recorded move; when every move after it stays legal a popup asks "Only change this move" or "Delete the moves after it" (otherwise they are deleted); Undo 6 s. No front/back split.
  - **Plan**: one position on `back`, with arrows (and circles). Needs at least one arrow. In Study (`PlanStudy`, also used for Summary) the board is bare and you draw the arrows yourself, colour group by colour group in `ARROW_COLOR_ORDER` (green → dark green → orange → dark orange → red → … ; 4 base colours each with a dark tint, palette in two rows); order inside a group doesn't matter. Arrows from an opponent piece are always the dark tint of their colour (stored that way when drawn; `effectiveArrowColor` maps older ones), dashed with a light halo, numbered among themselves, and drawn automatically when their group comes up. « ‹ › » take back / show a group or one arrow (a shown arrow is a slip once; a Summary is never scored); "Show all colors" is off by default on a Summary and on for Plan cards (when on: every light colour plus only the dark tint of the current family); when off (light + dark tint; a finished family stays until the next one has something on the board, also after the board is complete; "Show all colors" switch); badge positions are laid out once over all arrows so they never jump. In the board editor "Clear arrows" clears only what is shown (with "Only drawing color": that colour or the active threat). Summary only: the same move can carry several arrows in different colours (drawn side by side, `parallelOffsets` in `ChessBoard.tsx`), and arrows can belong to a threat (`notes.threat` = a letter, purple; badges "!A" on the opponent's move, "A1", "A2" on the answers). Your own threats (`notes.myThreat`, teal, `src/threats.ts`): "★A" on your threatening move, "A1", "A2" on the follow-up, opponent replies unlabelled and auto-played in Study. Whose move a threat arrow is (`arrowIsOpponent` in `ChessBoard.tsx`): the piece on its start square, else the piece at the start of a chain of arrows ending there, else the kind of threat (threat arrows are stored in their base colour, shown dark when the opponent's). Circles can belong to a threat too (`Circle.threat` / `Circle.myThreat`, threat colour, shown only in that threat). The board editor has two panels, "Opponent threats" and "My threats", each with "+ Threat" and letter chips (drawing or tapping a square while a chip is active tags the arrow or circle; the active chip has an × that deletes that threat with Undo; drawing any arrow over a threat arrow removes it); in Study threats are chips under the navigation buttons in two rows (Opponent threats, My threats), outside the colour order: tap one to draw its answers in order, tap again to return. Old `threat: true` migrates to "A". The notes editor has a "Link" dropdown. Arrows can carry `notes` (`ArrowNotes`: `reason`, `next`, `responses[{trigger, text, kind: 'reaction' | 'exception'}]`, cleaned by `arrowNotes.ts`) that appear as a popup in Study.
  - **Others / Front & back**: independent `front` and `back` faces (position, annotations, text); the only mode with a flip button.
  - Others/Plan keep a linear move history per face (`BoardFace.moves`); rewinding and playing another move truncates it. A board made from an opening's start position keeps the start's moves in `setupMoves` and its face moves start after them; imported and older boards start from the standard position. Always replay face moves from `faceBaseState(board, face)` (never from the standard position: Nxc6 from d4 crashed the editor); `sansForBoardMoves` never throws.
- **Board style** is one global setting. **Orientation**: a Black repertoire renders boards flipped everywhere via `flipIndex` (display layer only; never change `squareIndex`/`squareFromIndex`).
- **Example repertoire**: seeded per color by `exampleContent.ts` (always derived through the real engine, never hand-written), shown/hidden from Home, restorable from its row menu. **Repertoire list auto-skip** when there's one visible repertoire (Settings toggle overrides).
- **Migration**: `storage.ts` `migrate()` backfills fields added later. When changing the data shape, always add a backfill there and keep old data (and old backups) loadable.

## Import and AI import

- `src/importOpening.ts` (`parseOpeningImport`): turns pasted JSON (`format: "chess-playbook-import"`, `version: 1`) into an opening with Plan cards. Every move is replayed through `chessEngine`, every arrow and note is validated; one error = nothing is created. Entered via "Import PGN" behind **Add opening** (`ImportPgnOverlay`).
- `src/aiImport.ts` + `AiImportOverlay`: sends a pasted PGN to Gemini, runs the answer through the same checker and asks the model to fix errors (2 rounds). **Testing only**: the API key is typed in and stored on the phone; before other people get the app, these calls must move to a small server that holds the key.
- Format, limits, summary syntax, card styles and arrow rules: **`docs/IMPORT_REGELS.md`** (read it before making or reviewing opening content).
- Dev aid: Settings → Developer toggle enables `DevExportOverlay`/`devExport.ts`, which dumps a repertoire as plain text.

Public config and the Google Web client ID live in `src/firebaseConfig.ts` (identifiers, not secrets). Firestore rules: only `users/{uid}/**` for that same uid.

- Backup (`backup.ts`): the whole store as JSON → gzip (`pako`) → base64, at `users/{uid}/backups/{ms}` (payload over ~100 KB is split into `chunks/` documents). The last 10 are kept. Each carries device name, counts and a hash.
- Phone-side state is in its own AsyncStorage key `chess-flashcards-backup-meta` (not in the store, so the data format is untouched).
- Auto backup (`autoBackup.ts`): 60 s after a change (max one per 10 min), when the app goes to the background, shortly after start/sign-in, with retries; skipped when nothing changed. **Nothing is uploaded until the account's existing-backup question is settled** (`resolvedUid`; `backupFlow.ts`), and a phone with only the example repertoire never uploads.
- Restore replaces the local store; the previous store is kept under `chess-flashcards-data.before-restore` for Undo. UI: `AccountSection` at the top of Settings; a reminder on Home after 3 own cards when signed out.

## Engine (Stockfish)

The board editor shows an eval bar, a top-3 moves panel (tap a move to play it) and best-move arrows (hidden where the recorded line branches). Under the board a collapsible **Explorer** panel (`ExplorerPanel`, `src/lichessExplorer.ts`) shows the Lichess opening explorer for the position (database Lichess 2200–2500 blitz/rapid/classical or Masters, remembered; tap a move to play it). It needs a personal Lichess token, typed in under Settings → Lichess (`LichessSection`, AsyncStorage key `lichess.token`, not in the backup); one request at a time, answers cached for the session. Plan and Summary boards have a **Generate plan** button (`src/planGenerator.ts`, `GeneratePlanDialog`; no AI): it walks the explorer from the position (heaviest lines first, at most 160 positions; your move = most played unless a nearly as popular one scores clearly better; opponent moves with ≥ 12% of the games), keeps your moves that come in ≥ 60% of the lines; a move you play always is light (colour by when it comes: green, orange, red, blue), a move that answers a **threat** is drawn with that opponent move in the same dark tint (at most 4 opponent moves, one colour family each). A threat (`threatens()`, as in Jonas's Italian): it takes something, gives check, attacks one of your pieces (trade offers too), puts a piece (not a pawn) on your half, or attacks a pawn more often than it is defended (!Qb3 on f7); the answer (`answers()`) takes back or takes the piece, moves the attacked piece, answers the check or chases the piece. Quiet opponent moves (!g3, !f4, !h3, castling) are never reactions or exceptions. A pair is only drawn when both pieces stand on the move's start square in the board position (or get there by another drawn move: !Bg5 then !Bh4, kept together); a pair that needs moves not on the board (!Nxf6+ after c4, Nc3, Ne4) is dropped, so no arrow starts on an empty square. Exceptions (a threat after which a light move is mostly not played, by a piece that is on the board or comes there by a drawn move) become `responses` notes, single-move reactions (threats only) are returned for the Opening map, an empty Description is filled with "Key moves: … / Key reactions: !X => Y / Source: Lichess explorer (…)" (`planDescription`), and optionally each light move is checked against Stockfish's top 3 (`engine.analyzeOnce`). Depth 2–6, "Plan move from" (share of the lines: 60% default, 50%, 40%, 30%; lower gives more arrows where the opponent has many options), database and engine check are chosen in the dialog (remembered); the plan arrows on the position are replaced, threat arrows kept, Undo in the snackbar. New opening → **Opening map (Lichess)** (`src/openingMap.ts`, `OpeningMapOverlay`): after the start position is picked, the explorer is scanned (your move = most played, or the one you pick among popular alternatives; opponent moves ≥ 15%; 6 of your moves deep); at each opponent decision the followed moves get a plan signature (your moves common in the next 3 of yours), similar ones are merged, and a decision with two or more groups (each ≥ 15% of all games) is a split, at most two levels deep. Then `src/openingBuilder.ts` proposes the cards in the style of Jonas's Italian (shown with checkboxes; Create saves only the ticked ones, links to unticked cards are dropped): a **Summary** at the opening's start (Generate plan from there: light plan; per group of the first split in each branch the opponent's move and your answer in one dark tint, linked to its card; root pairs inside a split or a forcing line are dropped; single-move reactions as threats A, B … linked to their board); a **Specific line** Reactions card per forcing group (`isForcing`: two or more captures or checks in the first six moves; `groupLine`: the group's moves, your moves, opponent moves reached in ≥ 10% of all games, 4 of your moves deep); a **Reaction: !X** Plan card for a quiet group that changes 3 or more of your moves (otherwise only its dark pair on the Summary); **Reactions: first move** (one board per single-move reaction, at most 6: red circle on the opponent's piece, green arrow, text "If !X => Y"); and the opening summary tables (Start; Reply with a merged row for the first opponent decision when all its moves get the same plan, "4. !c3 / !d3 / !O-O | Nf6 d6", and one row per group; Piece, e.g. "BB | ?Bxe3 | !Be3", "NK later" when the piece moved before). Nothing is saved before Create. New opening → **Variations (Lichess)** (`src/variationMap.ts` `scanPlans`, `VariationMapOverlay`): the plans of the opening, one Plan card "Variations" with one board per ticked plan (at most 8), without arrows (Jonas draws them with Generate plan). Each board is on the plan's position: after the opponent move where the plan's main line leaves the closest line of another plan, then every move played in ≥ 70% of the games (`forced`), up to the next real choice; all moves from the standard start are kept in the board's history (`face.moves`), so the notation shows where it comes from. A **plan** is where your knights, bishops, queen and castling side go (rooks and pawns don't count); a new plan only starts where an opponent move sends one of your pieces to another square or route; the same plan by another move order is one plan ("Also after 5.Nc3"). Scan: your move = most played (chips for popular alternatives); opponent moves ≥ 15% there and ≥ 3% of all games, else the line goes on with the main move; 8 of your moves; the followed moves share all of a position's games (shares add up). Setup of a line: your first 6 moves only (`planMoves`); a move fixes a square only when ≥ 40% of the players choose it (`settle`, else the piece is open); a recapture (on the square the opponent just moved to) and not-yet-castled don't count, other captures do (...Nxe4); a piece taken within your first 6 moves doesn't count, taken later it keeps its plan square. Plans are merged bottom up when no piece is fixed on two squares (a plan's square = fixed in ≥ 60% of its games; fixed in one and open in the other counts half), plans under 5% of the games join the most similar one, then plans are merged again until stable. A Plan card's editor has "+ Add variations (Lichess)" (`openAddVariations`): the same scan, but your moves are the ones on the card's boards (`boardOverrides`; no "Your moves" chips), each board's own plan is the most played plan whose line goes through the board's position (hidden: "N plans are already on your boards"); a new plan that goes through a board's position "Continues from board 5" and is compared with that board, otherwise with the board it looks most like; new boards added up to 8. Every plan in both lists shows its position on a small board. Both screens list every plan that comes up in at least 2% of the games (`MIN_PLAN`), sorted from most to least played by the share of the plan's position (opponent choices from the start); a row shows the board, "After …" and the differences one per line ("Different from board 5:" / "Q h4 (board 5: d8)"), in Jonas's codes (NK d5, BW a6, BB g7, Q e7, K O-O); the board text has the plan's name, "After 5.Nxc6 bxc6 6.e5 Qe7 7.Qe2 Nd5 8.c4.", "Continues from board N.", the differences one per line, "Also after …", the share and the source. Generate plan adds its "Key moves / Key reactions" below a Description that has none yet (without a second Source line). The explorer keeps Lichess's opening names (`opening` on a position and on each move). The explorer waits a minute and retries on a 429; its answers are also kept on the phone (`lichess.cache2`, last 4000 positions; the old `lichess.cache` without names is removed). While a scan runs the screen stays on (`src/keepAwake.ts`, expo-keep-awake loaded lazily and guarded). Generate plan puts an exception only on the first plan move it changes. Hard-won constraints — read before touching:
- Hermes has no WebAssembly → the engine runs in a hidden `react-native-webview` page (`assets/engine/index.html`), talking UCI over `postMessage` (`src/engine/useStockfishEngine.tsx`).
- Android's WebView can't start a Worker from `file://`; `index.html` fetches the engine with `XMLHttpRequest` (success reports status 0; `fetch()` hangs), wraps it in a Blob and starts the Worker from that.
- WASM NNUE builds need SIMD, which faults on this phone. The engine is `stockfish-18-asm.js` (ASM.js, ~10.5 MB). Don't "upgrade" to WASM.
- These single-threaded builds crash if `position`/`go` arrives before the previous search's `bestmove`; the hook queues (`searchingRef`/`pendingRef`). Don't simplify it.
- `assets/engine/*.js` must stay in `metro.config.js`'s `blockList`; editing `assets/engine/` needs a native rebuild. UCI `MultiPV 3`; evals are flipped to White's perspective.

## UI/UX conventions

- Draw icons as `react-native-svg` paths, not Unicode glyphs (they don't center reliably).
- Boards inside a `ScrollView` use `PanResponder`, not `Pressable` (see `measureGrid`/`squareFromPage`/`arrowStartRef`).
- `useLayoutEffect` for anything that must apply before paint. Never call a hook after a conditional early return.
- Color language: `colors.primary` green = correct/yours; `colors.danger` red = wrong/destructive (`colors.dangerText` for red text); `colors.gold` = retry/warning. Opponent turn text is neutral grey.
- Touch targets are at least 48dp (`touchTarget`). Deleting is done without a dialog: a snackbar with **Undo** (6 s). Leaving an editor with changes asks "Discard your changes?". Every overlay handles the Android back button via `useOverlayBack`. Full-screen editors open without a fade.
- Numbered arrows: same-color arrows are numbered in the editor. Where a recorded Reactions line branches, the editor draws purple (`variationColor`) numbered arrows (1 = main line, which › plays; tap or play a move to follow it). In Study the variant arrows are numbered in walking order (main line last).
- Any new board-rendering code takes `flipped` and applies `flipIndex` to squares and every arrow/circle. Drawing: drag = arrow, tap = circle; the same arrow again in the same color removes it.
- When asked for UX feedback, cite the specific law from lawsofux.com and present findings as discussion points, not silent fixes.
